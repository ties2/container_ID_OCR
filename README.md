# Container ID Reading: Character Segmentation vs Detection

Reading ISO 6346 shipping-container codes from port-gate camera images.

Every character of the code is treated as its own instance. We compare
**per-character instance segmentation (YOLOv8n-seg)** with **per-character detection
(YOLOv8n)**, trained on exactly the same annotations, and measure how well each one
reads the full code. The repository also contains an earlier OCR-pipeline prototype
(detection → preprocessing → CRNN → ISO 6346 check); no trained weights are included for it.

The full method, data analysis and design decisions are in
[`doc/project_info.md`](doc/project_info.md).

```
CVAT annotations ─► prepare ─► YOLO seg / det datasets ─► train (MLflow) ─► evaluate (val) ─► test (once)
 code polygon +     Otsu masks, checks,   same images,                       localisation +
 box per character  stratified grouped    same split                         reading metrics,
                    persistent split                                         figure
```

---

## ISO 6346 format

```
 B M O U   6 7 2 5 7 3   7
 owner + category  serial  check digit (mod-11 over the first 10 characters)
```

Owner code: 3 letters. Category: `U` (freight), `J` (detachable), `Z` (trailer).
Validation lives in `src/models/postprocess.py` and is reused everywhere.

## Data layout

```
data/
├── 01_raw/archive/                  Kaggle download (not versioned)
├── metadata/                        selection sheets, versioned
│   ├── Label-camera-AH.csv …        file, group (G1–G8), layout, angle, condition, status, notes
│   └── images-camera-info.csv       images per camera and group
├── 02_interim/
│   ├── cvat_export/                 one CVAT export per task ("CVAT for images 1.1", with images)
│   │   ├── AH-G1/annotations.xml    versioned (your annotation work); images/ next to it
│   │   └── AH-G2/annotations.xml    all exports below cvat_export/ are merged
│   ├── labels.csv                   filename,container_id — versioned
│   └── split_assignments.csv        container → split, written by `make prepare` — versioned
└── 03_processed/char_dataset/       generated by `make prepare` (not versioned)
```

New annotations: export the new CVAT task into its own folder (e.g. `cvat_export/AS-G5/`),
add the codes to `labels.csv`, run `make prepare`. Old exports stay as they are.

A code that is cut off by the image border (or otherwise unreadable) is not annotated with
characters: draw one polygon with the CVAT label `ignore` over it. `make prepare` drops
everything inside it and paints the region out of the training image, so its unlabelled
characters are not learned as background.

To remove an image from the dataset permanently, set its `status` to `rejected` in its
selection sheet (`data/metadata/Label-camera-XX.csv`) and write the reason in `notes`.
It stays in CVAT, but `make prepare` skips it and lists it as `EXCLUDED` in `report.csv`.

## Workflow

```bash
# 1. Dataset
make prepare                         # masks, checks, split  -> data/03_processed/char_dataset/
make plot-data                       # image | ground truth | masks  (check before training)

# 2. Train (MLflow logs every epoch)
make train-seg SEED=42 EPOCHS=3      # quick timing test first
make train-seg SEED=42
make train-det SEED=42
make train-seg SINGLE_CLS=1          # all characters as one class: localisation only
make train-all                       # both models x seeds 42, 7, 123

# 3. Evaluate on the validation set (figure opens in PyCharm)
make evaluate RUN=seg-s42
make evaluate RUN=det-s42 N=0        # all validation images in the figure

# 4. Final numbers, once, at the very end
make evaluate RUN=seg-s42 SPLIT=test

# Dashboard and tests
make mlflow-ui                       # http://127.0.0.1:5000
pytest tests/
```

Variables: `DEVICE=0` (GPU), `IMGSZ=1280`, `EPOCHS=300`, `BATCH=4`, `SEED=42`,
`SINGLE_CLS=1`, `ARCH=yolov8n|yolo11n|yolov8s|yolo11s` (run name gets the arch, e.g.
`seg-yolo11n-s42`), `RUN=…`, `SPLIT=val|test`, `N=6` (rows in the figure, 0 = all).

**Rule:** settings are chosen on the validation set. The test set is evaluated once,
for the final table; otherwise test results start steering decisions (leakage).

## Git: what is versioned

Images, generated datasets, weights (`*.pt`), the MLflow store and figures stay local
(see `.gitignore`). Versioned: code, docs, `data/metadata/`, `annotations.xml`,
`labels.csv`, `split_assignments.csv` and the text summaries in `results/history/`.

To remove files that were pushed before they were ignored (they stay on your disk):

```bash
git rm --cached yolov8n.pt yolov8n-seg.pt          # example: weights in the root
git rm -r --cached --ignore-unmatch '*.DS_Store'
git commit -m "Stop tracking weights and OS files"
git push
```
